One authority per question

Five progress calculators, thirteen readings of one health fact, and two chances per turn for the same engine to answer. The audit found more than the directive assumed. This is what was removed, what remains, and what CI now refuses to let back in.

Why deleting engine pass 2 is provable, not a judgement call

second guard = front guard && !isTransactionReport — a strict subset. Every guard variable is computed above the front call and never reassigned between the two sites (verified). So any message able to satisfy the second guard had already been offered to the engine on that turn and declined. It could only re-roll the same model on the same preconditions.

And there was no pending state to change the answer: !multiFact and !isTransactionReport together mean the intervening handlers have essentially nothing to commit.

Proof

What CI now refuses

All of it graded on the final outbound text, with production branches enabled and the verifier running — not on a handler's draft.

The harness was lying, and that comes first

check() took () => void and did try { fn(); passed++ }. An async check incremented passed the instant its promise was created; assertions ran afterwards and rejections surfaced as unhandled promises, not failures. Two checks were already async, so two of its greens meant nothing.

Third time this harness could report success without exercising what it graded. It awaits every check now — and awaiting immediately exposed that "what are my steps" reached no deterministic door and fell through to the model, which has no step ledger.

Unresolved

Outside this cut

Two answers to one question product decision

my week returns a shareable image; this week returns text. Same seven days, same source — the report card is an adapter, so the numbers agree — but which one a client gets depends on the word they type. That is a product call, not a refactor.

The forecast derives its own per-day rows flagged

trajectory-report.ts answers will I lose weight from per-day intake and step pairs. The truth object exposes aggregates, not rows, so it queries the tables itself. It is a different question with its own model, not a second progress authority — but it is the one place two paths compute from the same tables.

The users-row workout counter still drifts flagged

Every progress claim now reads workoutLogs. Two non-progress uses remain and are asserted by name: a veteran gate (≥12 sessions unlocks supplements) and the session label on a workout card. Both read a column that drifts from the log table the moment one write fails.

The governor's counters pre-existing

Red since before the first cut. Modules rose by one this cut — health-state.ts, which the directive explicitly permits as a legitimate non-authoritative module. Architecture judged by ownership, not by counters, as instructed.

Deploy state unverified

The health endpoint is unreachable from the build container — the outbound proxy returns 403. Everything here is pushed to main. Whether Railway is running it has to be checked from outside.
